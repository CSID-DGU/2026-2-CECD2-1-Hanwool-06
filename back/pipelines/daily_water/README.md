아리수 일별 상수도 사용량 수집 파이프라인입니다. 등록부의 일일 수집 대상에 대해 과거 확정 검침과 최근 미결산 검침을 합쳐 수집합니다.

결과는 `APP_DATA_DIR/daily/water/<date>.csv`와 날짜별 상태 파일에 저장합니다. 기본 경로는 `data/runtime/daily/water/`입니다. 전체 갱신에는 `python -m back.pipelines.refresh --water`를 사용하며 날짜 범위 등은 [상위 문서](../README.md)를 참고하세요.

스마트검침 카드의 누수위험·계량기 장애 표시·실시간 사용량·아리수 갱신 시각은 `APP_DATA_DIR/arisu/<고객번호>.json`에 저장합니다. 사이트에 없는 상태는 안전이나 정상으로 추정하지 않습니다. 역 상세의 '아리수 원격검침(실시간)' 카드에 누수위험·실시간 사용량·계량기 상태를 보여 주고, 몇 시 기준인지(카드 갱신 시각)와 마지막 확인 시각을 적습니다. 계량기 상태는 마지막 검침이 카드보다 오래됐을 때만 그 검침 시각을 따로 붙입니다. 모델 위험도와는 섞지 않습니다. 실시간 사용량은 자정 검침 기준이라 대개 전날 확정 사용량과 같으므로 일일 사용량 그래프와 모델 입력에는 넣지 않습니다.

화면은 스냅샷 게시가 늦어져도 `daily/water`에 저장된 지난 날짜의 정상 사용량을 반영합니다. 모델 결과가 아직 없는 날짜도 실제 사용량은 표시하며, 예측과 위험도는 분석 완료 후 갱신됩니다.

서버 수집 기능이 켜져 있으면 아리수 누수위험과 계량기 상태를 00·12·18시에 확인합니다. 08시는 전체 수집이 같은 카드와 일별내역을 읽으므로 그것이 08시 확인입니다. 이 작업은 스마트검침 카드와 일별내역의 날짜별 상태만 저장하고, 사용량 CSV·과거내역·청구서·모델은 건드리지 않습니다. 서버를 다시 켜면 빠진 회차는 한 번만 확인합니다. 로그인 거부가 확인되면 다음 로그인 성공(08시 수집이나 수동 업데이트) 때까지 상태 확인을 멈춥니다. 08시 수집에서 카드 조회가 실패해도 안내 문구만 남기고, 그날 수집의 성공·재시도·실패 메일 판단에는 넣지 않습니다.

과거내역은 `APP_DATA_DIR/raw/remote_meter/<고객번호>/history/<시작월>_<종료월>.json`, 일별내역은 같은 폴더의 `day/<조회일>.json`에 원본 응답을 보관합니다. 정상 이외의 상태와 아직 확정되지 않은 행도 포함합니다. 모델용 CSV에는 분석 가능한 정상 관측만 저장하되, `상태`와 시·분을 포함한 `검침일자`를 보존합니다. 기존 날짜만 있는 CSV는 다음 조회에서 갱신됩니다.

같은 고객 폴더의 `statuses.json`에는 날짜별 검침 상태와 검침 시각을 모읍니다. 위험도 달력은 검침 상태가 정상이 아닌 날 모서리에 빨간 점을 찍고, 그날을 고르면 `계량기 장애`·`통신 장애` 등 아리수 원문 상태를 보여 줍니다. 과거의 장애를 지금 상태로 바꾸지 않습니다.

이전 `detector.py`는 [`archive/back/pipelines/daily_water/`](../../../archive/back/pipelines/daily_water/)에 보관했습니다. 현재 이상 탐지는 `back/ml/lightgbm/` 모델을 사용합니다.
