# 실제 자료로 로컬 채팅 확인

저장소 루트에서 실행합니다. Python 3.10 이상과 Node.js, 기존 API 의존성이 필요합니다. 이미 사용하는 Python 환경이 있다면 그 환경을 활성화하세요.

```sh
python -m pip install -r back/api/requirements.txt
npm install --workspaces
python -m back.api.dev_chat --remote-snapshot
```

기존 `.env`의 `OPENAI_API_KEY`, `OPENAI_MODEL`, `CHAT_STORAGE_*` 설정을 읽습니다. 스크립트가 `.env`를 수정하거나 키를 출력하지 않습니다. 설정 항목은 [대화 에이전트 안내](chat-agent.md)를 참고하세요.

프런트를 빌드한 뒤 `http://127.0.0.1:8011`에서 실제 FastAPI와 프런트를 함께 제공합니다. 포트를 바꾸려면 `--port 8012`, 빈 포트를 자동으로 배정하려면 `--port 0`을 붙입니다. 프런트 코드가 바뀌지 않았으면 `--no-build`로 기존 빌드를 사용할 수 있습니다.

## 격리되는 자료

실행할 때마다 운영체제 임시 폴더에 새 데이터 디렉터리를 만듭니다. `APP_DATA_DIR`와 `APP_DB_PATH`를 모두 이 위치로 지정하므로, `.env`나 터미널에 다른 경로가 있더라도 기존 `data/runtime/app.sqlite3`를 열거나 재초기화하지 않습니다. 저장소에는 등록부 초기 자료가 없으므로(2026-10-22에 뺌) 임시 DB에는 계량기가 없고, 역을 묻는 질문은 조회할 계량기가 없다는 답이 나옵니다. 실제 등록부로 확인하려면 운영 서버의 로컬 검증 안내를 따르거나, 버킷 DB 백업을 복원한 DB를 쓰도록 이 스크립트를 보완해야 합니다. 기존 DB의 사용자·세션·대화·추가 계량기는 복사하지 않습니다.

실제 NCP의 게시 스냅샷은 기존 읽기 전용 코드로 내려받아 임시 폴더에 저장합니다. 대시보드와 상세 화면은 이 사본을 읽고, 채팅은 요청할 때 실제 NCP와 OpenAI를 사용합니다. 실행 중 NCP에 새 버전이 게시되면 채팅이 더 최신 자료를 볼 수 있으므로 비교하려면 서버를 다시 실행하세요. `--remote-snapshot`을 생략하면 상세 화면은 저장소의 기존 자료를 사용합니다.

자동 수집 워커, Object Storage 업로드 훅, 메일 발송은 이 프로세스에서 꺼집니다. 원격 객체를 쓰거나 삭제하지 않습니다. 채팅 질문을 보내면 실제 OpenAI 호출이 발생합니다.

## 로그인과 확인

터미널에 나온 `로그인 정보 파일`을 열면 `email`과 `password`가 있습니다. 매번 새로 만드는 로컬 전용 관리자이며 비밀번호는 터미널 출력과 명령 인수에 남기지 않습니다. 파일 권한은 소유자만 읽고 쓸 수 있는 `0600`입니다. 이 파일의 내용을 저장소나 공유 문서에 붙이지 마세요.

1. 안내된 로컬 URL에 접속하고 임시 계정으로 로그인합니다.
2. 화면에 보이는 역과 수집 날짜로 상태를 질문합니다. 예: `2026년 10월 20일 역삼역 상태 알려줘`.
3. 이어서 `전날은?`을 보내 대화 문맥이 유지되는지 확인합니다.
4. 답변 아래 출처를 눌러 상세 화면의 계량기·날짜·사용량·위험도 달력 선택을 비교합니다.
5. 관측값은 있지만 분석 결과가 없으면 미분석으로, 관측값 자체가 없으면 자료 없음으로, 관측 오류는 자료 확인으로 구분되는지 확인합니다. 상세 화면에서도 사용량과 위험도 분석 결과 유무를 따로 확인합니다.
6. 아래 질문으로 날짜별 조회, 문맥 유지, 장기 집계와 RAG 검색을 확인합니다. 각각의 답변은 같은 NCP 스냅샷의 값과 대조합니다. 데이터가 갱신되므로 특정 횟수나 사용량을 고정된 정답으로 사용하지 않습니다.
7. Enter로 보내자마자 입력칸이 비워지고 질문 말풍선이 보이는지 확인합니다. 답변을 기다리는 동안 다음 질문을 써도 응답이 이를 지우면 안 됩니다. 전송이 실패하면 빈 입력칸에는 원래 질문이 복구되고, 이미 쓴 새 질문은 유지됩니다. `다시 시도`는 실패한 질문을 다시 보내며 새로 쓴 질문을 보존해야 합니다. 한국어 조합 중 Enter는 전송하지 않고, Shift+Enter는 줄바꿈합니다.

### 처음 화면의 예시 질문

각 질문은 `새 대화`에서 시작합니다. 최근 7일은 원격 자료의 최신 날짜까지, `오늘까지`는 달력상 오늘까지를 뜻합니다.

| 질문 | 확인할 내용 |
|---|---|
| `최근 7일 동안 경고가 나온 역을 알려 주세요` | 전체 일치 건수와 최근 상세 목록을 구분하는지, 같은 역의 여러 날짜를 별개의 역으로 세지 않는지 확인합니다. |
| `경복궁역은 2025년 1월 1일부터 오늘까지 주의가 몇 번 있었나요?` | 기간이 길다는 이유로 거절하지 않는지, 전체 집계와 실제 분석 자료가 있는 날짜 범위를 함께 설명하는지 확인합니다. |
| `석촌역의 최근 7일 사용량을 그 전 7일과 비교해 주세요` | 두 기간의 합계와 증감이 맞는지, 어느 쪽이든 유효한 관측일이 7일보다 적으면 완전한 주간 비교로 단정하지 않는지 확인합니다. |

### 최초 설계의 질문 7개

처음 세 질문은 같은 대화에서 차례대로 보냅니다. 연도를 생략한 날짜는 문맥과 자료 범위에 따라 해석되므로, 답변에 표시된 연도를 확인하고 불명확하면 명시합니다. 나머지 질문도 앞서 선택한 역·날짜가 필요한 경우 같은 대화에서 이어서 확인합니다.

| 질문 | 확인할 내용 |
|---|---|
| `9월 20일 역삼역 상태 알려줘` | 해당 날짜의 실제 사용량·예측값·저장된 판정과 출처 날짜가 맞는지 확인합니다. 없는 자료는 없다고 설명해야 합니다. |
| `그날 사용량 얼마나 늘었어?` | 앞서 질문한 역·날짜를 유지하고, 예측량·전날 등 어떤 기준과 비교했는지 명시하는지 확인합니다. 기준 자료가 없으면 증감 수치를 만들면 안 됩니다. |
| `왜 경고가 떴어?` | 실제 판정이 경고인지 먼저 확인하고, 사용량 차이와 원인 후보·확인된 원인을 구분하는지 확인합니다. |
| `역삼역 최근 일주일 상태는?` | 최근 7일의 실제 상태와 사용량을 요약하고, 미분석·자료 확인·자료 없음 날짜를 정상과 구분하는지 확인합니다. |
| `9월에 경고였던 역들 알려줘` | 요청한 달 전체의 경고 판정을 집계하고, 일부 최신 상세만 표시하면 그 사실을 밝히는지 확인합니다. |
| `비슷한 누수 사례가 있었어?` | 권한 내 등록된 검증 사례만 인용하는지 확인합니다. 사례가 없으면 누수 사고나 조치 결과를 만들어 내면 안 됩니다. |
| `경고가 뜨면 뭘 점검해야 해?` | 등록된 점검 매뉴얼에 근거하는지 확인합니다. 관련 문서가 없으면 확인된 지침을 찾지 못했다고 안내해야 합니다. |

긴 기간을 조회할 때는 요청한 시작일·종료일과 실제 사용량·분석 자료의 첫날·마지막 날을 구분해 확인합니다. 첫날과 마지막 날 사이에도 누락된 날짜가 있을 수 있으므로 유효 자료 수와 누락 자료 수도 봅니다. 분석 자료가 일부만 있는 기간의 `주의 0건`은 확보된 분석에서 일치 항목이 없다는 뜻이며, 요청한 전체 기간에 이상이 없었다는 뜻이 아닙니다. 여러 계량기를 조회한 경우 건수는 계량기·날짜 단위이고, 서로 다른 역 수나 사고 수와 다릅니다. 일별 상세가 최대 120행 또는 이상 상세가 최대 11건으로 줄어도 전체 집계는 요청 범위의 모든 저장 자료를 포함해야 합니다.

`Ctrl+C`로 종료하면 임시 DB·로그인 파일·다운로드한 스냅샷을 지웁니다. 강제 종료나 시스템 중단으로 남은 폴더는 터미널에 안내된 `water-chat-dev-...` 경로를 확인한 뒤 직접 삭제할 수 있습니다. 재실행하면 새 계정과 새 대화로 시작합니다.

이 실행 경로는 로컬 검증용입니다. 배포 시에는 [기존 배포 절차](../deploy/README.md)를 따릅니다.
